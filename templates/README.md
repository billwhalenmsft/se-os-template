# Templates

These templates turn a synthetic or authorized request into a scoped,
reviewable artifact.

| Template | Purpose |
|---|---|
| `inputs\cs-use-case.md` | Capture a customer-service use case without raw source bodies |
| `scoping\template.md` | Define outcome, scope, evidence, and approval boundaries |
| `demo-script\template.md` | Build a general five-beat demo narrative |
| `demo-script\cs\template.md` | Build a customer-service-specific demo narrative |
| `demo-guide\template.md` | Prepare a delivery guide |
| `demo-guide\motion-matrix.md` | Choose a synthetic motion pattern |
| `workspace\` | Canonical workspace placement policy and thin AI-tool adapters |

Committed examples must use Contoso, Fabrikam, Northwind, or another clearly
fictional organization. Real engagement material belongs in a private instance.

For workspace scaffolding and the read-only placement checker, start with the
[workspace template](workspace/README.md). It is a generic convention, not a
customer inventory, an automatic migration, or a host sandbox.
