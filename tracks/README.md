# Tracks

A track is a reusable practice-area scaffold. It groups a charter, vertical
context, use-case patterns, and quality expectations without embedding customer
data.

## Included tracks

| Track | Purpose |
|---|---|
| [AI Business Process](ai-business-process/) | Process automation, service, sales, and Power Platform patterns |
| [AI Workplace](ai-workplace/) | Collaboration and knowledge-work patterns |
| [Cloud and AI Platforms](cloud-ai-platforms/) | Azure platform and AI application patterns |
| [Security](security/) | Security-focused outcome and architecture patterns |
| [Discrete manufacturing compatibility path](discrete-mfg/) | Redirect for the seeded manufacturing vertical |

## Add a track

1. Create `tracks\<track-name>\TRACK_CHARTER.md`.
2. Define the business outcome, target personas, and measurable proof.
3. Use fictional organizations in committed examples.
4. Add local or private context only in a generated private instance.
5. Validate before proposing a reviewed reusable pattern.
